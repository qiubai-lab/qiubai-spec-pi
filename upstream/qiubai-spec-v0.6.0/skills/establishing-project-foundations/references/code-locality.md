# Code Locality And File Growth

目标是让一次行为修改在有限且相关的代码范围内完成理解、编辑和验证。文件规模是预警信号，职责和理解路径决定处理方式；不以减少文件行数或读取 token 数代替正确性。

## Project Warning Policy

创建或明确调整工程基线时，按语言、框架和文件类型选定项目预警策略。复用已有 linter/分析工具；可执行配置是阈值事实源，`ENGINEERING_STYLE_SPEC.md` 或已有等价文档仅记录意图、范围和命令入口。

小项目默认采用简单策略：选一个适用于手写源码的规模预警值和统计口径，复用工具或一次简单统计；超线或新增冲突职责时人工评估，生成/锁文件不计入。无需增长基准、分类阈值矩阵、专门脚本或例外登记系统。数值依据项目实际选择，不要求先做全仓库统计研究。

只有持续增长已造成问题、多团队协作需要治理、不同文件类型确有不同需求，或用户明确要求时，才扩展下列策略；只增加解决当前问题的项：

- 范围：手写源码、测试、声明文件等分别适用哪些规则。
- 度量：总行数或非空非注释行数等所选工具口径；不要混用统计结果。需要时补函数规模或复杂度信号。
- 数值：给出具体文件规模预警值，以及明显增长的数值判据（如绝对增量，或带最小增量的相对比例）。已有项目参考同类正常文件与受影响样本，新项目参考选定生态和预计职责；写明选择理由，不把通用数字当行业标准。
- 动作：新文件越线、已有文件跨线、已超线文件继续明显增长或新增职责时，必须完成职责评估；不是自动拆分命令。
- 例外：生成代码、锁文件、供应商代码、数据夹具按明确路径/类型分类。生成文件应指向源和生成命令；手写大文件不能靠伪装 generated 绕过检查。

普通功能任务使用已有策略；没有策略时聚焦明显职责混合和实际增长风险，不要求为当前任务先建立治理配置，也不擅自持久化新阈值。预警配置不能延误必要行为保护。

## Review And Disposition

对触发预警的受影响文件，回答：主要职责是什么，本次为何增长，新增内容是否属于它，拆分是否减少理解范围和编辑风险？

- 多职责、独立变化原因或可独立测试的规则：沿业务职责拆分，保持公开契约与行为保护。
- 单一且紧密相关的实现：可以保留，说明具体理由和后续重新评估条件；“旧文件本来很大”不是理由。
- 生成/数据文件：在其源或数据组织层面处理，不手工切割生成结果。

已有超大文件无需一次清理，但不能无理由接收新职责。例外限定路径和范围；长期例外按已有 context 授权机制保存，当前任务处理结论留在 spec/验证记录。不要关闭全局规则来通过本次检查。

## Local Understandability

小文件也可能难理解：函数混合参数解析、业务决策、存储和异常处理，或存在隐式状态与副作用，都可触发检查，不等到超过行数才处理。

相关规则、类型和行为测试尽量靠近；公开接口明确必要的输入、输出、错误和副作用。复杂约束在拥有它的实现附近解释原因，避免把注释变成重复代码的流水账。

沿一个实际修改场景检查“入口 → 规则 → 外部边界 → 测试”的理解路径。避免多层无意义转发、全局 barrel 和过细文件切分；有隔离/复用价值的层次可以保留。跨文件跳转数不设统一上限，审查其必要性。

## Reading And Editing

先用 Directory Map、文件搜索或符号索引定位入口，再读相关符号和必要上下文；根据实际依赖扩展到调用方、契约、初始化和测试。避免默认全文加载多个大文件或无关目录。

局部片段不足以判断状态、作用域、副作用或不变量时必须扩大读取，必要时读完整文件。工具输出截断不是已完整理解的证据；先缩小定位范围再补齐。已有仍适用的上下文可复用，文件变化后检查相关内容是否过期。

优先局部补丁或语言语义重构工具，避免无必要的整文件重写。编辑后检查 diff、调用关系及相关验证，保护用户未提交内容。不为降低上下文消耗跳过关键行为保护。

## Executable Feedback And Acceptance

检查范围聚焦当前受影响文件。简单策略只需规模信号和职责判断；仅启用增长规则时比较任务开始状态或项目明确基线，缺少可靠基准时报告，不能将未知增长当作零。新职责即使增量小也要评估。既有未触及大文件不阻塞当前任务。

规模预警可以保持 warning；已要求处理的预警没有结论时，验证不能声称全部通过。若项目选择机器门禁，则区分超线信号与未处理违规，失败正确传递退出码；豁免需有具体适用理由。

新增或修改自动检查时，用隔离夹具验证正常文件、超线/增长文件及合法排除项，确认告警和退出行为符合策略。规模工具只提供信号，不宣称证明职责或理解成本。

当前任务适用的验收包括：目标规则与测试可通过明确入口定位；新增职责归属合理；触发预警的文件有处理结论；拆分后没有多余转发或模糊接口；相关行为验证仍通过。记录实际观察与限制，不承诺未经测量的 token 或效率收益。
