# Baseline Rules

必须项约束适用范围内的结果；默认项允许以项目事实说明偏离原因；条件项仅在触发时采用。用户选择、语言和框架要求优先于示例布局，不为统一外观迁移已有项目。

| Area | Rule | Level |
| --- | --- | --- |
| 定位 | 明确真实入口、模块职责、允许依赖和验证位置 | 必须 |
| 理解与编辑 | 建立项目文件规模预警及处理方式，保持行为修改路径局部清晰 | 必须 |
| 结构 | 按业务能力聚合相关实现；测试按生态惯例就近或镜像组织 | 默认 |
| 边界 | 跨模块只使用公开契约，不访问私有实现；模块依赖避免循环 | 必须 |
| 规则 | 核心业务规则能脱离 UI、HTTP 和具体存储细节测试 | 涉及核心规则时必须 |
| 分层 | 出现冲突职责、复杂规则或外部依赖隔离需求时才拆层 | 条件 |
| 命名 | 使用一致领域术语和生态命名习惯，名称表达职责 | 必须 |
| 共享 | 有真实消费者、相同语义和明确归属后才提取共享内容 | 默认 |
| 环境 | 显式依赖、适用版本约束、无秘密的配置示例、可复现命令 | 必须 |
| 检查 | 相关检查可非交互运行，失败传递非零退出码 | 必须 |
| 知识 | 同一规则只有一个事实源，其他位置引用 | 必须 |
| 扩展 | 独立部署、隔离或容量需求明确时考虑服务拆分 | 条件 |

## Module Contracts

为实际模块说明职责、公开能力、允许依赖和副作用边界。使用语言可见性、包 exports 或检查器约束访问；单独存在 `public.ts`/`index.ts` 不等于边界已经生效。

跨模块用例确定一个编排责任方。发现循环时先重新划分职责或抽取真正独立的契约；不要用事件总线掩盖循环。跨模块数据库访问同样可能绕过所有权，不能仅凭 import 合规判定架构合规。

Domain、API DTO 和存储模型的语义与生命周期要区分；简单映射不必生成三个完全相同的类。复杂规则避免被框架或 ORM 形状控制。适配器依赖核心定义的接口，由组合入口装配；不把所有技术设施全局注入所有模块。

## Naming And Sharing

- 同一概念统一术语；概念不同即明确区分，不为统一拼写消除领域差异。
- 用例以意图命名，如 `cancelOrder`，布尔值表达判断含义；类型、文件、目录按语言和框架惯例，不强制跨语言 kebab-case。
- 测试名称表达受保护行为，并能定位对应模块；生成文件标明来源和再生成命令。
- 避免无归属的 `utils`、`helpers`、`manager`。按具体能力命名，业务状态保留在拥有它的模块。
- 按 [code-locality](code-locality.md) 设置项目文件规模预警并处理增长信号；不设跨语言硬上限，不为了每文件一个符号强拆紧密相关实现。职责混合和无意义跨文件跳转同样需要检查。
- 不预建通用 repository、插件系统、事件总线或全局 shared。允许暂时重复，确认语义稳定后再提取。

## Sources Of Truth

| Knowledge | Canonical location |
| --- | --- |
| 模块职责、依赖方向、架构取舍 | `docs/qb-spec/context/ARCHITECTURE_SPEC.md` 或已有等价文档 |
| 命名、命令入口、工程约定和适用范围 | `docs/qb-spec/context/ENGINEERING_STYLE_SPEC.md`；可执行细节以配置为准 |
| 稳定目录职责与入口索引 | `docs/qb-spec/DIRECTORY_MAP.md` |
| 需要长期保留的关键决策及理由 | `docs/qb-spec/context/DECISIONS.md`，只在确有重要取舍时创建 |
| 当前变更的目标和验收 | 当前 change spec / plan |
| 人类快速启动指南 | 已有 README，引用真实命令入口 |
| Agent 上下文发现 | 规范 Agent 入口，仅维护短路由 |

有足够清楚的现有事实源时复用并记录路径，不创建同义规范。按需创建文档，不预建所有 context；自动化配置记录机器规则，文档记录意图和入口。后续普通变更遵守已采用基线，不自动提升新偏好。
