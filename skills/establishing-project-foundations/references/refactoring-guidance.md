# Refactoring Guidance

用于已有项目的结构与工程基线演进。只解决有证据的问题，保留有效结构；局部整理沿用普通开发流程，不要求完整诊断。

## Diagnose And Bound

按受影响入口、调用方、模块依赖、数据所有权和检查配置追踪问题，不默认扫描整个仓库。记录：

- 问题证据：具体代码位置、依赖链、重复规则或不可运行的检查。
- 实际影响：定位、修改范围、测试隔离或回归风险受何影响。
- 根因及未知项：区分事实、推断、已有失败和本次新增问题。
- 目标边界：职责迁到哪里、哪些契约公开、允许哪些依赖。
- 保留范围：哪些结构和行为保持不变；最低限度做到什么即可结束。

例如，规则散落在多个 handler 且无法独立测试，支持抽取规则；目录不整齐本身不支持全仓库搬迁。文件数、行数、层数和抽象数量不是改善目标。

受影响大文件持续增长、职责混合或理解一次行为需多次无意义跳转时，按 [code-locality](code-locality.md) 诊断。比较修改前后的实际理解路径、规则归属和编辑范围；不能仅凭拆成更多小文件宣称改善，也不因未超过阈值忽略复杂度。

## Behavior Baseline

纯重构保持可观察行为。按风险记录输入输出、错误语义、副作用、权限、事务、顺序和性能约束中实际相关的部分；不为每项生成空表。运行已有相关检查，记录重构前状态。

覆盖不足时交给 `protecting-critical-behavior` 建立必要保护。现状刻画测试记录必须保留的行为，不把所有历史输出当成正确需求；已知缺陷明确标注，修复与结构迁移尽量分步验证。已有高信号覆盖充分时直接复用，不强制新测试或先写失败测试。

公共契约变化、数据迁移或功能替换须明确记录 Behavior Delta 和兼容验收；不能用“重构”略过这些变化。纯结构调整使用 `design`，Delta 可说明不适用及受保护不变量。功能中的局部重构保留原 change type；tier 按实际影响、可逆性和未知项确定，高风险迁移走 strict，不凭文件数升级，不新增 refactor type 或迁移生命周期。

## Migration Design

把 Foundation Decision 放入当前 spec/plan，不另建方案文件。每个有意义的步骤说明修改范围、受影响调用方、兼容方式（如需）、验证动作和恢复方式。普通可逆源码移动可按步骤恢复，无需引入运行开关；数据和部署恢复不能假设 Git 回退就足够。

| Situation | Approach |
| --- | --- |
| 文件移动、命名调整 | 优先语言语义工具；检查静态引用、动态导入、资源路径、导出和构建配置，不把文本替换当成完整验证 |
| 业务规则抽取 | 保护现有行为，再抽取规则，逐个切换调用方 |
| 模块边界调整 | 定义公开契约，迁移访问路径，再限制私有访问；同时检查绕过模块的数据访问 |
| 大型实现替换 | 有必要时以稳定接口暂存新旧实现，逐步切换；普通调整不添加双实现 |
| 子系统接管 | 有真实运行需求时分阶段接管，并明确路由、状态一致性和恢复条件 |

每步保持受影响项目可运行、可验证。新增抽象应对应当前替换需求，不预建万能框架。功能修正和机械移动尽量分开，避免无法归因的混合 diff。

临时适配层、旧入口和开关记录消费者及移除条件。完成一个迁移片段后检查旧路径是否仍有使用方，不能只凭静态搜索就排除外部消费者。

## Feedback And Stop Conditions

- 每步运行最直接的相关检查，失败先归因，不继续堆积迁移。尊重用户未提交修改，不用全仓库 reset 恢复自己的步骤。
- 发现新的契约变化、范围扩大或缺失的关键保护时，回到当前 spec/plan 补充或缩小迁移；只在缺口改变已批准范围时澄清，不重新启动整个流程。
- 无法建立必要行为证据时，报告阻塞、可完成的安全子范围和复验方式，不承诺行为等价。
- 已达到目标边界和验收后停止，不顺手扩大为全仓库风格治理。

## Acceptance

以当前问题选择可观察验收，不套统一指标：

- 行为保持：受保护场景与契约继续成立，声明的 Delta 另有验证。
- 结构改善：目标循环消除、私有访问移除或规则有唯一归属；如新增检查规则，用负例确认其有效。
- 可测试性：目标规则在约定的隔离条件下接受测试。
- 工程反馈：受影响范围有可运行检查，错误正确传递。
- 迁移收尾：调用方切换完成，过渡结构按计划清理；必须保留的内容说明理由和退出条件，不宣称已全部迁移。
- 知识一致性：Directory Map 反映真实结构；context 只保存已批准的长期决定。

`checking-architecture-boundaries` 检查职责与依赖，`writing-qb-plans` 组织步骤，`verifying-before-completion` 汇总上述证据；本参考不另设默认执行链。
